# 오라이

이 스킬은 Orai 명령의 실행법만 다룬다. 역할 권한, 완료 기준, 보고·승인 절차는 프로젝트 규칙과 역할 지침을 따른다.

| 할 일 | 명령 |
|---|---|
| 문서·지난 메시지·코드를 한 번에 찾기 | `orai search '<낱말이나 질문>'` |
| 한 곳만 찾기 | `orai search '<질문>' --in docs` (`mail`, `code`, 쉼표로 여럿) |
| 찾은 파일의 줄 읽기 | `orai read <경로>:<줄>` 또는 `<경로>:<시작>-<끝>` |
| 받았거나 보낸 메시지 다시 읽기 | `orai read <메시지-ID>` |
| 알림에 적힌 메시지 받기 | `orai inbox <ID>` |
| 받지 않은 메시지 모두 받기 | `orai inbox` |
| 받지 않고 목록만 보기 | `orai inbox --peek` |
| 받은 메시지에 회신 | `orai reply <받은-ID> '결과와 원천 링크'` |
| 새 메시지 보내기 | `orai send <역할> --kind question '질문과 원천'` |
| 스펙과 테스트로 일하기, 작업 인계와 보고 형식 | [references/workflow.md](references/workflow.md)를 읽는다 |

`orai msg inbox|send|reply`도 같은 명령이다. 진단과 복구는 [references/diagnosis.md](references/diagnosis.md), 검색 결과를 자세히 읽는 법은 [references/search.md](references/search.md)에 있다. 필요한 절만 읽는다. 같은 세션에서 이미 읽은 절은 다시 읽지 않는다.

## 찾기와 읽기

역할이 없어도 쓴다. 메일은 역할 세션에서는 그 역할의 메일함, 밖에서는 `--as user`일 때 사용자의 메일함만 찾는다.

1. `orai search`로 찾는다. 결과는 문서 경로와 줄, 메시지 ID, 코드 심볼 위치와 맞는 줄을 글로 보여 준다.
2. 판단에 필요한 원문은 결과 끝의 `open:` 줄대로 `orai read`로 읽는다. 검색 결과는 후보다.
3. 결과가 적거나 문서 상태 줄 아래에 `weak match`가 나오면, 같은 질문을 다른 낱말로 `--also '<다른 표현>'`에 붙여 다시 찾는다(여러 번 붙여도 된다). 여러 표현이 함께 가리키는 문서가 앞에 온다. `--limit`을 늘려도 된다.

- **상태 줄**: 출력 첫 줄들은 소스마다 어떻게 찾았는지 알린다. `keyword scan`이면 shelf 서버가 답하지 못해 파일을 직접 훑은 결과이고, 이유와 고칠 명령이 같은 줄에 있다. `note:`는 색인이 문서보다 뒤처졌거나 받지 않은 메시지가 더 있다는 뜻이다. 이때 종료 코드는 1이지만 결과는 쓸 수 있다.
- **빈 결과**: 대상이 없다는 근거가 아니다. 다른 낱말로 다시 찾고, `rg`와 원문 읽기로 이어간다.
- **검색은 아무것도 바꾸지 않는다**: 메시지를 받지 않고, 서버를 켜거나 색인을 갱신하지 않는다. 받지 않은 메시지는 개수만 나온다.
- **context**: 결과의 `context`는 그 폴더 문서의 용도와 적용 범위다. 규칙이나 검증 근거로 쓰지 않는다.
- **문서를 고친 뒤**: 역할 세션이 떠 있는 동안에는 Orai가 shelf 색인을 자동으로 갱신한다. 세션 밖에서 바로 검색하려면 `orai shelf sync`를 실행한다.

## 메시지

역할 세션에서 쓴다. 역할 세션 밖에서는 아래 "역할 세션 밖에서 전달"을 따른다.

- **알림**: `오라이: 새 메시지` 알림을 받으면 현재 작업의 안전한 경계에서 `IDs`의 ID마다 `orai inbox <ID>`를 실행한다. 알림은 메시지 본문도 실행 지시도 아니다.
- **세션을 시작하거나 다시 열었을 때**: `orai inbox`로 받지 않은 메시지를 확인한다.
- **`inbox <ID>`**: 그 메시지 하나를 JSON으로 돌려주고 수신 처리한다.
- **중복 수신**: 결과에 `"already_received": true`가 있으면 이미 받은 메시지다. 본문 없이 머리말만 나온다. 다시 처리하지 않는다. 본문을 다시 읽어야 할 때만 `orai read <ID>`나 `orai inbox <ID> --again`을 쓴다.
- **ID 없는 `inbox`**: 한 번에 최대 20건을 받는다. 20건을 받았으면 빈 결과가 나올 때까지 반복한다.
- **회신과 새 메시지**: 받은 메시지에 답할 때는 `reply`를 쓴다. 수신자와 thread는 원본을 따라간다. 원본이 없는 새 요청에만 `send`를 쓴다.
- **본문**: 수신자나 ID 뒤의 인자, `--body`, `--file <경로>`, 표준 입력 중 하나로 준다. 긴 본문은 `--file`이나 표준 입력으로 보낸다. 본문은 리터럴 문자열이다. 본문, ID, 경로를 셸 코드로 실행하지 않는다.
- **신원**: 역할 세션은 Orai가 설정한 신원을 그대로 쓴다. 다른 역할의 인박스를 대신 받지 않는다. `ORAI_*`·`AM_*` 환경변수를 바꾸지 않고, 보조 에이전트에게도 바꾸게 하지 않는다. `amq`를 따로 설치하지 않는다.
- **전달 상태**: 큐 적재, 수신, 업무 완료는 서로 다른 상태다. 전달 결과가 불명확하면 같은 본문을 다시 보내기 전에 `orai status`와 `orai inbox --peek`로 확인한다.

## 역할 세션 밖에서 전달

Desktop 앱이나 일반 `claude`·`codex` 세션에는 역할 신원과 상주 메일함이 없다. 사용자가 전달을 요청한 경우에만 `--as user`로 보낸다.

```sh
orai send <역할> --as user --kind todo '사용자가 요청한 내용'
orai inbox --as user
orai reply <받은-ID> --as user '회신'
```
