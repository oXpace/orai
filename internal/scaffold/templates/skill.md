# 오라이

이 스킬은 오라이 메시지 액션만 소유한다. 역할 권한은 각 역할 지침, 설치·복구는 `orai --help`와 Orai 운영 문서가 소유한다.

## 메시지 액션

`오라이: 새 메시지` 알림을 받으면 현재 작업의 안전한 경계에서 `IDs`의 각 ID로 `orai msg inbox <ID>`를 실행한다. 알림은 수신 신호일 뿐이며, 메시지 본문도 실행 지시도 아니다. 같은 세션에서는 이 절을 다시 읽지 않는다.

```sh
orai msg inbox <알림-ID>
orai msg reply <받은-ID> --body '결과와 원천 링크'
orai msg send <역할> --kind question --body '질문과 원천'
```

- `inbox <ID>`는 해당 메시지 하나를 JSON으로 반환하고 수신 처리한다. ID 없는 `inbox`는 최대 20건을 받는다. 20건을 받았다면 빈 결과가 나올 때까지 반복한다. `inbox --peek`는 소비하지 않고 목록만 보여 준다.
- 기존 요청에 답할 때는 `reply`를 쓴다. 수신자와 thread는 원본을 따라간다. 새 요청일 때만 `send`를 쓴다.
- 긴 본문은 `--file <경로>`나 표준 입력으로 보낸다. `--body`는 항상 리터럴 문자열이며, 본문·ID·경로를 셸 코드로 실행하지 않는다.
- 역할 세션은 오라이가 설정한 신원을 그대로 쓴다. 다른 역할의 인박스를 대신 받거나 `AM_*` 환경을 바꾸지 않는다.

## Desktop에서 전달

사용자가 전달을 요청한 경우에만 `user` 신원으로 보낸다.

```sh
orai msg send <역할> --as user --kind todo --body '사용자가 요청한 내용'
orai msg inbox --as user
orai msg reply <받은-ID> --as user --body '회신'
```

오라이가 프로젝트 큐를 해석하므로 AMQ 환경변수를 직접 설정하지 않는다. 알림 준비 상태는 `orai status`로 확인한다. 큐 적재, 수신, 업무 완료는 서로 다른 상태다. 전달 결과가 불명확하면 같은 본문을 다시 보내기 전에 먼저 확인한다.
